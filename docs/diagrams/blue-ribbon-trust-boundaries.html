Derived, not documented

  • Produced by weir sys with no run and no implementations — only the .edge, .node and .topology files
  • A zone is one line in a topology; a crossing is an edge between differently-zoned nodes
  • The carries annotation is the classification: labels on the crossing edge's own fields

The same report took two hand investigations in the project it describes.

The proxy became a type

  • Two of five county adapters route through app.fetchgis.com, behind an interface identical to the direct ones
  • Same signature, same shape, different party on the other end — nothing in the types distinguished them
  • It lived as a sentence in OPEN_ITEMS.md: "a different trust posture than every other adapter"

A zone genuinely cannot be inferred from the data or the contract. It has to be declared by somebody who knows where the code runs.

† And one answer is wrong

  • RawParcelFeature reports carrying nothing — while holding a county's entire response, owner names included
  • Because its payload is an opaque JSON string, so no field carries a label
  • A leakage query that under-reports is worse than none; it is a false negative, and weir records it as an open question rather than a feature

The untyped hop swallowed it — which turned out to be true of serialized fields on typed edges too.
