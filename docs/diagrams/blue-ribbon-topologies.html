The program, as weir sees it

Four topologies, drawn from the declarations. Rectangles are nodes, ellipses are edges — which is not a stylistic choice: weir's execution model is a Petri net, where edges are the places that hold tokens and nodes are the transitions that fire. The picture alternates between them because the program does.

main.topology · zone: server · ParcelRequest → ParcelIdentity

The entry point. Three of its nodes run somewhere else, and each sits inside a zone — a dashed boundary around the node, not a box in place of it. Every arrow crossing one of those boundaries is a network hop, which is exactly what weir sys reports as a crossing. routeCounty is the only branch; resolveIdentity is the only fan-in, and it waits for two edges that are nine steps apart in lineage.

the three referenced topologies · one effect node each

Each is one node wide, and the zone wraps the node — the declared input and output edges sit outside it, which is what makes them the contract rather than the contents. A topology is the unit of placement, so a single node that runs somewhere else needs its own topology to say so.
