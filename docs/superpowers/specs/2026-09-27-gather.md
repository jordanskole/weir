# `gather`: the dual of spread

Status: draft.

## Motivation

`spread` gave weir data-driven fan-out: one alert becomes N entities, each taking its own treatment with its own lineage. The dual has no expression at all. Raised 2026-09-27 by the outside reader who wrote the original `soc-triage` sketch, reading the committed example:

> One alert → N entities → independent work per entity → rejoin each entity's branches. It does **not** do: N entity assessments → one alert assessment. That's the scatter/gather operation a real SOC triage workflow immediately wants.

`examples/soc-triage` ends with N `Assessment` instances and nothing that can say anything about the alert as a whole. That is not a missing convenience; it is half of an operation.

Named before being built (design-history.md, "`gather` is `sequence`"): gather is `sequence : t (f a) → f (t a)`, and spread + per-element subgraph + gather is `traverse`. Two consequences of that naming are load-bearing below — the failure policy (§4) and the empty case (§5) — and both would otherwise have been decided by taste.

## 1. What makes it hard, and what makes it tractable

Gather is a join, but not the one weir has. An `allOf` node's cardinality is **statically known**: the declaration lists the edges, so "am I complete" is answerable from the contract. A gather's cardinality is **decided at runtime** by the spread that produced the elements, so completeness cannot come from the declaration.

The first framing of this (open-questions.md) concluded it needed "a lineage-scoped barrier the pulse loop has no notion of", which is true and made it sound much worse than it is.

**The collection token records the count.** `spread` logs the collection it was given (`Many_Entity`) alongside the element instances it materialized — kept so a vectorized consumer stays reachable (2026-09-26-spread-materializes-elements.md §1). Every descendant reaches it by ordinary lineage:

```
Assessment ← EntityEvidence ← IdentityContext ← Entity ← Many_Entity
```

So the barrier has a **known target**: fire when N instances of the gathered edge descend from this collection, where N is that collection's size. No global quiescence, no new notion of doneness — a count, and a lineage walk that already exists.

That the collection is available at all is a consequence of a decision taken for an unrelated reason. Worth noting as evidence for keeping it rather than treating it as dead weight.

## 2. Declaration

A new input kind, alongside `single` and `allOf`:

```yaml
# declarations/summarizeAlert.node
label: Summarize Alert
input:
  gather: Assessment
output: AlertAssessment
```

`gather: X` says: *collect every `X` descended from one spread, and fire once with the collection.* The payload is a keyed collection, the same shape a `many` output produces — keyed by the gathered edge's own `index`, per design-history.md's "`many` is a collection, keyed by index, not an array".

**Which spread it gathers from is not declared, and must not be.** It is the collection ancestor shared by the candidates — the same nearest-common-ancestor question `joinRows` already answers, asked of a collection token instead of an ordinary instance. Declaring it would make a node's contract depend on the topology above it, which is the property `soc-triage` demonstrates weir does *not* have: `investigateIdentity` says `Entity → IdentityContext` and knows nothing about being one of N.

## 3. Readiness

For a node declaring `gather: X`, in one pulse:

1. Take the unconsumed `X` candidates on declared arcs — `eligibleForEdge`, unchanged.
2. Group them by the nearest collection ancestor in their lineage: the highest-`seq` ancestor logged under a `Many_*` edge name.
3. A group is **complete** when its size equals that collection's entry count.
4. Fire once per complete group, consuming the whole group.

An incomplete group yields no candidate and is retried next pulse, which is how every readiness rule here already behaves — the same reason an `allOf` group that never completes reaches quiescence rather than spinning.

## 4. Failure: all-or-nothing, because that is what `sequence` means

If one element's subgraph produces `Failed<In>` instead of the gathered edge, the count never reaches N and the group never completes. Left there, the gather hangs until the budget stops the run — a silent stall, which is this repo's worst failure mode.

`sequence`'s signature settles it: `t (f a) → f (t a)` means a single failure makes the whole result a failure. **Resolved: a gather whose group can no longer complete fails as a whole**, emitting `Failed<In>` under the usual synthesized edge, so the topology may route it like any other failure.

"Can no longer complete" is decidable without waiting: a group is dead when, for some element of the collection, a `Failed_*` instance descends from it. That is the same lineage walk step (2) already performs, asked of the failure edges.

Recorded rather than deferred because the alternative — gather what succeeded — is a real option that some workflows want, and choosing it should be a declaration the author makes, not a default they inherit. Not built here.

## 5. The empty collection

`traverse` over an empty collection yields an empty collection. A spread of zero elements must therefore let its gather fire **immediately, with an empty collection** — never hang waiting for the first of zero things.

This is the case most likely to be missed, and it is not hypothetical: `extractEntities` returning no entities is an ordinary outcome for an alert that names nothing recognizable. Named here so the test exists.

## 6. What this does not need

**`input: many X`.** Gather produces a collection token and fires *its own* node with it, so the consumer is the gather node itself. The vectorized consumer stays a separate, still-unbuilt thing: it consumes a collection someone *already produced*, where gather *builds* one. Sequencing them the other way round — vectorized input first — would not have helped.

## Testing

Break-proofs required for each. `tsconfig.json` excludes `src/**/*.test.ts`, so test files are never typechecked.

1. A `gather: X` node fires **once** with a collection of every `X` descended from one spread, keyed by each element's own index.
2. It does **not** fire while the group is incomplete, and does fire on the pulse the last member arrives. Assert both, not just the second: a rule that fires early would pass a final-state check.
3. Two spreads in one run gather separately — N entities from alert A do not land in alert B's collection. The lineage equivalent of the cross-entity pairing `assembleEvidence` was fixed for.
4. An empty collection gathers immediately to an empty collection (§5).
5. A group with a failed element fails as a whole, routing to the synthesized `Failed_*` edge, rather than hanging until the budget (§4).
6. `examples/soc-triage` gains `summarizeAlert`, and the run produces exactly one `AlertAssessment` naming both entities.
7. A property on the gather node relating its output to **every** element — not one — since a fan-in property that names a single input is the false green fixed in `2d9ba58`.

## Explicitly out of scope

- **`input: many X`**, the vectorized consumer (§6).
- **Gather-what-succeeded** as a declarable policy (§4).
- **Nested gathers.** A gather of a gather is `join`'s territory — flattening `Many (Many X)` — and is a different operation with different laws (design-history.md, "`gather` is `sequence`").
- **Cross-correlation gathering.** Nothing joins across runs, by design.
